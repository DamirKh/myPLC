# Выводы после отладки

Дата: 2026-10-19.

## Что было сломано и почему

### 1. Индикатор не мигал

`ba.timer` в Xedge32 останавливает callback, если тот возвращает управление.
Повторяющаяся логика должна быть coroutine-циклом с `coroutine.yield(true)`.

Исправлено для циклов управления, истории и RGB-индикатора. Правило добавлено
в `AGENTS.md`.

### 2. Не хватало RMT-каналов

На практике Xedge32/ESP-IDF даёт **4 RMT-канала**, а не 8. Три шины 1-Wire
занимают TX+RX каждая, плюс RGB — ещё один TX. В итоге `control_b` и RGB не
создавались.

Текущее решение — программный мультиплексор:

- RGB создаётся первым, RMT TX, 10 МГц;
- для 1-Wire по очереди открывается одна RMT-пара на нужной шине (10 МГц);
- после чтения пара закрывается;
- опрос шин последовательный, цикл датчиков — 10 с.

Риск: надёжность частого открытия/закрытия RMT и работа на длинных линиях ещё
не проверены на реальных датчиках.

### 3. Падение приложения при старте

`indicator.color()` возвращает таблицу `{r,g,b}`, а `rgb:write()` ожидал три
числа. Ошибка `attempt to compare table with number` останавливала `.preload`,
из-за чего приложение исчезало из списка запущенных.

Исправлено: цвет разбирается на три компонента, `rgb:write()` также понимает
таблицу.

## Регистрация приложения в Xedge32

- `.appcfg` — управляемый Xedge файл. Нельзя менять его напрямую через WebDAV:
  приложение может потерять регистрацию.
- Правильный путь: **Firmware Update & App Upload** → загрузить ZIP →
  выбрать **Unpack ZIP file (developer-mode)** → затем в IDE
  правый клик по приложению → **Configure App** → включить **Running** и
  **Auto Start** → Save.
- Если приложение падает при старте, Xedge убирает его из списка запущенных.
  Для диагностики удобно временно запустить каталог через `xedge.auxapp` в
  LuaShell32 — тогда ошибка видна в последовательной консоли.

## Отладка через USB

- Порт: `/dev/ttyACM0`, 115200.
- Открытие порта перезагружает ESP32, возможна повторная энумерация USB.
  Нужен устойчивый реконнект и `DTR=false`, `RTS=false`.
- Полезные проверки:
  - `/api/state.lsp` — состояние приложения;
  - `getappsstat` — запущенные приложения;
  - последовательный лог — ошибки Lua, RMT и Wi-Fi;
  - `xedge.auxapp` — быстрый запуск каталога для отладки.

## Текущее состояние

- Xedge32 4.4, ESP32-S3 N16R8.
- Приложение установлено, запущено, `Auto Start` включён.
- `/api/state.lsp` отвечает `200`.
- Датчики не назначены: `faults=["no_valid_room_sensor"]`, насос выключен,
  RGB мигает красным — это ожидаемое поведение.
- Реальные DS18B20, SSR и насос ещё не проверялись.
- Пожелание про «живой» heartbeat-индикатор остаётся в `docs/future.md`.

## Следующие шаги

1. Подключить датчики, проверить поиск ROM на всех трёх шинах.
2. Назначить `room`/`floor` на `control_a` и `control_b`, остальные — на `diag`.
3. Проверить стабильность программного мультиплексирования RMT на реальных
   линиях.
4. Проверить SSR без насоса, затем подключить насос через защитную цепь.
5. Проверить аварийные сценарии и только после этого оставить автозапуск.
