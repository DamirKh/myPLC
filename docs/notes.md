# Выводы после отладки

Дата: 2026-10-19.

## Что было сломано и почему

### 1. Индикатор не мигал

`ba.timer` в Xedge32 останавливает callback, если тот возвращает управление.
Повторяющаяся логика должна быть coroutine-циклом с `coroutine.yield(true)`.

Исправлено для циклов управления, истории и RGB-индикатора. Правило добавлено
в `AGENTS.md`.

### 2. Не хватало RMT-каналов

На практике Xedge32/ESP-IDF даёт **4 RMT-канала**, а не 8. Три шины 1-Wire
занимают TX+RX каждая, плюс RGB — ещё один TX. В итоге `control_b` и RGB не
создавались.

Текущее решение — программный мультиплексор:

- RGB создаётся первым, RMT TX, 10 МГц;
- для 1-Wire по очереди открывается одна RMT-пара на нужной шине (10 МГц);
- после чтения пара закрывается;
- опрос шин последовательный, цикл датчиков — 10 с.

Риск: надёжность частого открытия/закрытия RMT и работа на длинных линиях ещё
не проверены на реальных датчиках.

### 3. Падение приложения при старте

Функция индикатора возвращает таблицу `{r,g,b}`, а `rgb:write()` ожидал три
числа. Ошибка `attempt to compare table with number` останавливала `.preload`,
из-за чего приложение исчезало из списка запущенных.

Исправлено: `rgb:write()` понимает таблицу цвета.

## Регистрация приложения в Xedge32

- `.appcfg` — управляемый Xedge файл. Нельзя менять его напрямую через WebDAV:
  приложение может потерять регистрацию.
- Правильный путь: **Firmware Update & App Upload** → загрузить ZIP →
  выбрать **Unpack ZIP file (developer-mode)** → затем в IDE
  правый клик по приложению → **Configure App** → включить **Running** и
  **Auto Start** → Save.
- Если приложение падает при старте, Xedge убирает его из списка запущенных.
  Для диагностики удобно временно запустить каталог через `xedge.auxapp` в
  LuaShell32 — тогда ошибка видна в последовательной консоли.

## Отладка через USB

- Порт: `/dev/ttyACM0`, 115200.
- Открытие порта перезагружает ESP32, возможна повторная энумерация USB.
  Нужен устойчивый реконнект и `DTR=false`, `RTS=false`.
- Полезные проверки:
  - `/api/state.lsp` — состояние приложения;
  - `getappsstat` — запущенные приложения;
  - последовательный лог — ошибки Lua, RMT и Wi-Fi;
  - `xedge.auxapp` — быстрый запуск каталога для отладки.

## PIN для настроек

- Админка вынесена в `/admin/` и защищена 4-значным PIN.
- PIN хранится как PBKDF2-SHA256-хеш с солью в `config.security`.
- Ввод PIN — экранная цифровая клавиатура (0–9, C, ⌫) с маскировкой точками;
  встроенная клавиатура телефона не нужна. Есть отдельная кнопка «Войти».
- Первый PIN — `/setup.lsp`, только пока PIN не задан и только с доверенной LAN
  (loopback или тот же IPv4 `/24`).
- Сессия — подписанная HttpOnly-cookie на 30 минут, привязана к IP.
- 5 неверных попыток — блокировка на 5 минут.
- Смена PIN — `/admin/pin.lsp`; блокировка — `/admin/lock.lsp`.
- CSRF-токены подписаны ключом `ba.aeskey` в памяти и живут 1 час.
- Проверено на устройстве: setup → PIN → settings → sensors; неверный PIN и
  неверный CSRF отклоняются; смена PIN и lock работают.
- Сканирование датчиков теперь асинхронное: страница запускает его и
  автоматически обновляется; результат появляется после завершения.
- RMT-вызовы, которые уступают управление колбэкам, нельзя оборачивать в
  `pcall` — Xedge32 выдаёт `attempt to yield across a C-call boundary`.
- При отсутствии датчиков страница показывает «Датчики не найдены» и подсказку
  проверить питание, DQ и подтяжку 4.7 кОм.
- Проверено на устройстве: скан без датчиков завершается, `service_mode`
  снимается, ошибок yield больше нет.
- Xedge Authentication — отдельная авторизация для `/rtl/`, WebDAV и Web File
  Manager.

## Override уставки

- Публичная уставка теперь не перезаписывает базовую: она создаёт временный
  override на 2 часа (или до события расписания).
- «Снять override» возвращает базовую уставку или расписание.
- Базовая уставка настраивается в `/admin/settings.lsp`.
- Проверено на устройстве: set 23 → target 23, override active; clear → target 22,
  override inactive.

## Компактный режим и автономность

- На экране уже 640 px автоматически включается компактный вид.
- Переключатель «Компактный/Полный вид» хранится в `localStorage` отдельно на
  каждом устройстве.
- На главном компактном экране: помещение, пол, уставка, насос; статус —
  насос/авария/override. Wi-Fi в интерфейсе не дублируется: нет сети — синий
  слот RGB в общей последовательности состояний.
- В компактном виде уставка скрыта: панель с −/+ открывается нажатием на
  плитку «Уставка» и закрывается по ×, клику вне панели или Escape.
- Если с панелью нет взаимодействия 1 минуту, она закрывается автоматически;
  таймер сбрасывается при касании, клике или нажатии клавиш.
- Уставка на телефоне меняется кнопками −/+ с debounce 2.2 с под rate-limit API;
  границы изменения задаются в настройках (`public_setpoint_min/max`).
- Базовая уставка должна входить в заданные границы — это проверяется при
  сохранении конфигурации.
- Подача/обратка, датчики и диагностика — в раскрывающейся секции «Подробнее».
- На главной — ЖК-часы `ЧЧ:ММ`: семисегментные цифры, мигающее двоеточие,
  локальное время по `utc_offset_minutes`. При несинхронизированном времени
  показываются прочерки.
- Светлая и тёмная темы: переключатель в шапке, выбор в
  `localStorage` (`thermostat.theme`). Без сохранённого выбора берётся
  `prefers-color-scheme`. Тема применяется до отрисовки страницы через
  `/static/theme.js`, поэтому нет вспышки светлого фона.
- Часы следуют теме: светлый полупрозрачный корпус с тёмными сегментами,
  тёмный корпус с зелёными сегментами. Остальные элементы используют общие
  CSS-переменные.
- Состояние MQTT видно в шапке: зелёная иконка — подключено, красная — включено,
  но связи с брокером нет; при выключенном MQTT иконка скрыта.
- Опечатка в host MQTT раньше приводила к попыткам DNS и тормозила интерфейс.
  Теперь адрес проверяется при сохранении и перед созданием клиента; невалидный
  host отклоняется без запуска подключения.
- Все ресурсы (CSS, JS, SVG, шрифты system-ui) локальные; внешних CDN и
  интернет-запросов нет.
- Проверено в Playwright: 390×844 — компактно, 4 плитки; полный вид показывает
  детали; выбор сохраняется после reload; внешних запросов нет.

## Wi-Fi AP/STA

- `/admin/wifi.lsp` переключает STA ↔ AP, хранит SSID и зашифрованный пароль
  в `config.json` на устройстве.
- Пароль шифруется ключом softTPM (`ba.tpm.uniquekey`), не хранится в git/ZIP.
- STA ожидается 60 секунд, затем автоматический возврат в AP.
- `esp32.wscan()` на Xedge 4.4 в текущем режиме возвращает 0 сетей; SSID
  вводится вручную.
- Число AP-клиентов через Lua API недоступно; фиолетовый слот использует
  активность веб-интерфейса за последние 30 секунд.

## Текущее состояние

- Xedge32 4.4, ESP32-S3 N16R8.
- Приложение установлено, запущено, `Auto Start` включён.
- `/api/state.lsp` отвечает `200`; публичные обзор и уставка работают.
- PIN-защита реализована; тестовый PIN удалён, поэтому `pin_configured=false`
  и ожидается установка PIN через `/setup.lsp`.
- `/admin/` защищён PIN, `/setup.lsp` доступен только с доверенной LAN.
- Штатная Xedge Authentication для `/rtl/` ещё не настроена.
- Датчики не назначены: `faults=["no_valid_room_sensor"]`, насос выключен,
  RGB показывает слот аварии — это ожидаемое поведение.
- Реальные DS18B20, SSR и насос ещё не проверялись.
- RGB работает по слотам 1,2 с + пауза 0,4 с; зелёный слот присутствует всегда.
- Для полного зависания ESP32 остаётся добавить аппаратный watchdog.

## Следующие шаги

1. Подключить датчики, проверить поиск ROM на всех трёх шинах.
2. Назначить `room`/`floor` на `control_a` и `control_b`, остальные — на `diag`.
3. Проверить стабильность программного мультиплексирования RMT на реальных
   линиях.
4. Проверить SSR без насоса, затем подключить насос через защитную цепь.
5. Проверить аварийные сценарии и только после этого оставить автозапуск.
