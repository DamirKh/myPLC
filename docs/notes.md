# Журнал отладки и проверки

Нормативное поведение — в `docs/decisions.md`. Здесь — проблемы, причины,
исправления и проверки.

## Журнал отладки

### 2026-10-19 — Индикатор не мигал

`ba.timer` в Xedge32 останавливает callback, если тот возвращает управление.
Повторяющаяся логика должна быть coroutine-циклом с `coroutine.yield(true)`.
Исправлено для циклов управления, истории и RGB-индикатора. Правило закреплено
в `AGENTS.md`.

### 2026-10-19 — Не хватало RMT-каналов

На практике Xedge32/ESP-IDF даёт **4 RMT-канала**, а не 8. Три шины 1-Wire
занимают TX+RX каждая, плюс RGB — ещё один TX, поэтому `control_b` и RGB не
создавались.

Исправление — программный мультиплексор: RGB создаётся первым (10 МГц), для
1-Wire по очереди открывается одна RMT-пара на нужной шине и закрывается после
чтения; опрос шин последовательный, цикл датчиков 10 с. Риск на длинных линиях
не проверен.

Связанное решение — `docs/decisions.md`, разделы 3 и 3a.

### 2026-10-19 — Падение приложения при старте

Функция индикатора возвращала таблицу `{r,g,b}`, а `rgb:write()` ожидал три
числа. Ошибка `attempt to compare table with number` останавливала `.preload`,
и приложение исчезало из списка запущенных.

Исправлено: `rgb:write()` понимает таблицу цвета.

### 2026-10-26 — Приложение зависало без датчиков

Без настроенных датчиков сенсорный воркер вызывал `ba.sleep(10000)`, который
блокирует Lua-поток; все таймеры, включая LED, замирали.

Исправление: воркер не запускается, если в конфиге нет датчиков; супервизор
запускает его только при их наличии. Проверено: `led_tick` растёт, насос
выключен, `faults=["no_valid_room_sensor"]`.

### 2026-10-26 — Скан сетей ломал AP

`esp32.wscan()` в режиме AP переводит интерфейс в режим сканирования, и AP
перестаёт работать. Исправление: сканирование запрещено в режиме AP, кнопка в
`/admin/wifi.lsp` скрыта. Решение — `docs/decisions.md`, раздел 6b.

### 2026-10-26 — Насос включался из-за скачка времени

Интервалы `pump_exercise`/`min_on`/`min_off` считались по `os.time()`; после
NTP-синхронизации разница становилась огромной, и насос запускался на прокачку.
Исправление: контрольные интервалы переведены на монотонное время `ba.clock()`.
Решение — `docs/decisions.md`, раздел 4.

### 2026-11-06 — PIN нельзя было задать в AP

В AP-режиме клиент получает адрес из другой подсети, чем IP сервера
`192.168.190.0`, поэтому проверка `is_trusted` по первым трём октетам не
пропускала `/setup.lsp`.
Исправление: в AP-режиме проверка подсети пропускается, в STA остаётся
доверенная LAN. Решение — `docs/decisions.md`, раздел 6.

### 2026-11-06 — Дубли приложений Xedge

После ручной установки через WFM Xedge показывал несколько запущенных
приложений (`thermostat`, `Floor Thermostat`, `APP`, `-1`-варианты), все
запускали один `.preload`.
Причина: реестр приложений хранится в разделе `xcfg` (0x7f5000), а не только
в файле `xcfg.bin` в storage; удаление файла не очищало старые записи. Кроме
того, имя в `.config` (`Floor Thermostat`) не совпадало с каталогом
`thermostat`, из-за чего создавалась вторая запись.
Исправление: имя в `.config` приведено к `thermostat`; перед чистой установкой
стёрт раздел `xcfg` и файл `xcfg.bin`, затем ZIP установлен через `startApp` с
`deploy=false`. Проверено: в `getappsstat` остаётся одна запись
`{"thermostat":true}`.

## Операционные заметки

- Регистрация приложения в Xedge32: `.appcfg` — управляемый файл; не править
  через WebDAV. Правильный путь: **Firmware Update & App Upload** → загрузить
  ZIP → **Unpack ZIP file (developer-mode)** → в IDE правый клик по приложению
  → **Configure App** → включить **Running** и **Auto Start**. Если приложение
  падает при старте, Xedge убирает его из списка запущенных; для диагностики
  удобно временно запустить каталог через `xedge.auxapp` в LuaShell32.
- Отладка через USB: порт `/dev/ttyACM0`, 115200. Открытие порта может
  перезагрузить ESP32; нужен реконнект и `DTR=false`, `RTS=false`. Полезные
  проверки: `/api/state.lsp`, `getappsstat`, последовательный лог,
  `xedge.auxapp`.
- RMT-вызовы, которые уступают управление колбэкам, нельзя оборачивать в
  `pcall` — Xedge32 выдаёт `attempt to yield across a C-call boundary`.
- Опрос датчиков вынесен в отдельную worker-корутину; таймер-супервизор
  перезапускает её после ошибки и сбрасывает `sensor_busy`.
- `ds18b20.parse_scratchpad` проверяет все 9 байт: неполный ответ шины даёт
  ошибку чтения, а не Lua-исключение.
- Перед чтением ROM скан запускает конвертацию и ждёт 800 мс; иначе датчики
  после подачи питания показывают `85 °C` (`power_on_reset_85C`).

## Проверено

### PIN и доступ

Проверено: setup → PIN → settings → sensors; неверный PIN и неверный CSRF
отклоняются; смена PIN и принудительная блокировка работают.
Решение — `docs/decisions.md`, раздел 6 «Доступ».

### Датчики и сервисный режим

Проверено: таблица по шинам; сервисный режим выключает насос и ускоряет опрос;
роли, метки и смещения применяются атомарно; температура и статус обновляются
через htmx OOB-фрагмент без перезаписи редактируемых полей; стрелка ↑ помечает
максимальный рост; скан без датчиков завершается; `service_mode` снимается.
Решение — `docs/decisions.md`, раздел 5.

### История и моточасы

Проверено: «Комната» за 7 дней с шагом 10 минут хранит агрегаты; «Насос» за
24 часа с шагом 3 минуты хранит отдельные значения diag-датчиков; live-режим —
только в браузере; старый `history.jsonl` не используется; моточасы хранятся в
`runtime.json`.
Решение — `docs/decisions.md`, раздел 9.

### Override уставки

Проверено: set 23 → target 23, override active; clear → target 22, override
inactive. Popup выбора времени: по умолчанию 3 ч, шаг ±30 минут, максимум 6 ч;
сервер отклоняет превышение. На обзоре есть плитка «Текущая уставка».
Решение — `docs/decisions.md`, раздел 6a.

### Интерфейс и автономность

Проверено: компактный вид включается на экранах уже 640 px; выбор режима
сохраняется в `localStorage`; Playwright 390×844 — компактный вид, полный вид
показывает детали; темы применяются до отрисовки; состояние MQTT видно в шапке;
невалидный MQTT host отклоняется без DNS; htmx и все ассеты локальные, внешних
запросов нет.
Решение — `docs/decisions.md`, раздел 6a.

### Wi-Fi AP/STA

Проверено: джампер GPIO 10–11 принудительно включает AP; после снятия AP
удерживается до перезагрузки или ручного переключения в STA. Особенности:
`esp32.wscan()` на Xedge 4.4 возвращает 0 сетей, SSID вводится вручную; число
AP-клиентов через Lua API недоступно, фиолетовый слот использует веб-активность
за последние 30 секунд.
Решение — `docs/decisions.md`, раздел 6b.
