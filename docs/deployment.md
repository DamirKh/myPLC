# Прошивка и развёртывание

## Состояние платы

- ESP32-S3, 16 МБ flash, 8 МБ PSRAM.
- USB Serial/JTAG, порт `/dev/ttyACM0`.
- Прошита Xedge32 4.4 (сборка `esp32s3`, консоль USB Serial/JTAG).
- После заводской прошивки устройство стартует в AP-режиме.

## Заводская прошивка Xedge32

Использован образ `esp32s3/merged-xedge.bin` из
`https://realtimelogic.com/downloads/bas/Xedge32-S3-Firmware.zip`.

```bash
uvx --from esptool esptool \
  --chip esp32s3 --port /dev/ttyACM0 -b 230400 \
  --before default-reset --after hard-reset \
  write-flash 0x0 merged-xedge.bin
```

Заводская прошивка стирает NVS, storage и пользовательские приложения. Для
обновления уже настроенной платы лучше использовать OTA (`xedge.bin`) или
Firmware Update & App Upload, чтобы не потерять конфигурацию.

## Доступ к Xedge32

После прошивки:

1. Подключиться к Wi-Fi AP `xedge32`, пароль по умолчанию `12345678`.
2. Открыть `http://xedge32.local/rtl/` или IP платы.
3. Настроить Wi-Fi в LuaShell32:

```lua
esp32.netconnect("wifi", {ssid="ваш-SSID", pwd="пароль"})
```

4. После подключения к домашней сети открыть устройство по имени/IP.

Консоль: USB Serial/JTAG, 115200. После загрузки появляется `LuaShell32 ready`.

## Загрузка приложения

Собрать ZIP:

```bash
make package
```

В Xedge32:

1. Открыть меню (три точки) → **Firmware Update & App Upload**.
2. Перетащить `build/thermostat.zip`.
3. Распаковать/установить.
4. В IDE включить приложение, проверить запуск и включить `Autostart` только
   после проверки.

Важно: ZIP собирается из **содержимого** каталога `thermostat/`, чтобы `.config`
и `.preload` были в корне архива.

## PIN для настроек

Настройки защищены 4-значным PIN, без логинов и паролей.

Первый PIN задаётся только с доверенной LAN:

1. Подключиться к той же подсети, что и плата (или к AP `xedge32`).
2. Открыть `http://<IP>/setup.lsp`.
3. Ввести PIN и повторно подтвердить.
4. После этого `/setup.lsp` станет недоступен, а `/admin/` будет запрашивать PIN.

Публичный обзор и уставка работают без PIN. Настройки, поиск датчиков, роли,
расписание, MQTT и тест насоса находятся в `/admin/`.

- PIN хранится как PBKDF2-SHA256-хеш с солью, не в открытом виде.
- Сессия после ввода PIN — 30 минут, cookie HttpOnly.
- 5 неверных попыток — блокировка на 5 минут.
- Смена PIN — `/admin/pin.lsp`.
- Заблокировать сессию вручную — `/admin/lock.lsp`.
- Админские POST защищены CSRF-токеном и проверкой Origin.

PIN из 4 цифр — это защита от случайного доступа, а не от подбора в локальной
сети. Для удалённого доступа используйте VPN или HTTPS.

## Авторизация Xedge IDE

Это отдельная авторизация, не связанная с PIN приложения:

1. Открыть `/rtl/` → три точки → **Authentication**.
2. Создать локального пользователя.
3. Проверить, что `/rtl/`, Web File Manager и WebDAV требуют вход.
4. В эксплуатации IDE можно отключить через `xedge.ui(false)`.

Пока используется HTTP в LAN, пароли IDE видны в локальной сети. Для удалённого
доступа нужен HTTPS/VPN; SSO (Entra ID) требует HTTPS.

## Первый пуск

1. Подключить только датчики, без насоса.
2. Открыть страницу датчиков, выполнить поиск.
3. Назначить роли: `room`/`floor` на `control_a` и `control_b`, остальные — на
   `diag`.
4. Проверить температуры и калибровку.
5. Подключить SSR к низковольтной нагрузке, проверить активный уровень.
6. Настроить предел пола, гистерезисы, min on/off.
7. Подключить насос через защитную цепь.
8. Проверить аварийные сценарии: отключение датчика, отключение обеих пар,
   перезагрузка, потеря питания.
9. Включить `Autostart`.
